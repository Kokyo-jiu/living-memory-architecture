OVERVIEW

MEMORY THAT CAN EVOLVE

The first version of this project modeled memory as four layers. Long-running use changed the design. The current architecture separates persistent memory from active continuity, treats the relational database as canonical, makes the semantic index rebuildable, and lets retention follow meaning instead of a single timer.

The goal is still simple: remember what matters, retrieve what is relevant, preserve how understanding changed, and keep continuity without turning every trace into permanent memory.

PERSISTENCE

THREE PERSISTENT LAYERS

CORE
DURABLE ANCHORS
Identity, relationship foundations, durable principles, and information whose loss would break continuity.
LONG
LONG-TERM UNDERSTANDING
Milestones, preferences, patterns, important events, and accumulated understanding worth carrying forward.
SHORT
RECENT & WORKING CONTEXT
Recent observations, conversation records, temporary state, and details that may matter now without needing permanent storage.

Layer and retention are related but not identical. A short-layer category can be retained longer when its meaning requires it.

The vector database is deliberately treated as derived state. If indexing fails, the canonical memory still exists. The index can be repaired or rebuilt from the relational store instead of becoming a second competing truth.

RETENTION

RETENTION FOLLOWS MEANING

CATEGORY-AWARE RETENTION

Expiry is chosen by memory semantics rather than assuming every item in one layer deserves the same lifetime. Temporary runtime traces may expire quickly; recent autobiographical records may be retained; durable anchors remain permanent.

ACCESS & REVISION

Retrieval frequency, importance, explicit updates, and later corrections can all influence how memory is carried forward. Old information may remain traceable even after a newer memory supersedes it.

TIME

TEMPORAL GROUNDING

A memory system must distinguish when something happened from when the record was written or edited. Historical material imported today should not silently become evidence about the present.

PROVENANCE & MEMORY LINKS

Memory is not only a pile of documents. Links preserve how one record relates to another and how understanding changed over time.

Contradiction is allowed to exist. People change, memories are corrected, and two records can both matter because they describe different moments.

RETRIEVAL

HYBRID RETRIEVAL

KEYWORD

Exact names, dates, titles, phrases, categories and explicit references. Useful when precision matters more than association.

SEMANTIC

Meaning-based recall over the vector index, with layer and category filters. Useful when the wording changed but the underlying idea stayed related.

Retrieval remains selective. The system can combine recent context, exact matches, semantic matches and linked evidence instead of injecting the entire history into every response.

The aim is continuity without indiscriminate accumulation: enough past to understand the present, while keeping irrelevant history out of the immediate context window.

CONTINUITY

ACTIVE CONTINUITY IS SEPARATE

WAKE / SESSION RUNTIME
TRANSIENT AWARENESS & ACTION TRACES
Wake state, session state, reasoning state and tool-action traces belong to an active continuity plane. They may inform what the system does while active, but they are not automatically treated as long-term autobiographical memory.

This separation prevents a common failure mode: turning every operational trace into a permanent memory. Durable memory should be written deliberately, with semantics and provenance, instead of simply mirroring runtime logs.

EXTENSION

OPTIONAL GROWTH HOOKS

The memory system can provide temporally grounded, provenance-linked source material to a separate higher-level growth system. That growth architecture is intentionally outside the scope of this repository and can evolve independently.

EVOLUTION

FROM V1 TO V2

V1 · ORIGINAL MODEL

Core / long / short / consciousness as four peer layers, importance decay, promotion, auto-linking, dual-channel retrieval and context injection.

V2 · CURRENT MODEL

Three persistent layers, active continuity as a separate runtime plane, category-aware retention, canonical relational storage, recoverable semantic indexing, temporal grounding and richer provenance.

The original showcase is preserved in v1/index.html as a record of how the architecture grew.
